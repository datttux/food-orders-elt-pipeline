1. WHAT IS THIS PROJECT ABOUT?
--------------------------------------------------------------------------------
This project analyzes and builds an end-to-end data pipeline for an online food 
delivery company using the dataset 'food_orders.csv' (1,010 records).

The assignment consists of two major parts:
- PART 1: An exploratory data analysis and data validation study completed in 
          a Jupyter Notebook ('food_orders_analysis.ipynb'), covering Tasks 1 to 8.
- PART 2: A production-grade, modular, batch-based ELT (Extract-Load-Transform) 
          pipeline in Python, Pandas, and MySQL/SQL, processing data in batches 
          of 100 records and loading cleaned results into an analytics database.


2. PROJECT STRUCTURE & FILES EXPLAINED
--------------------------------------------------------------------------------
- food_orders.csv
  The raw source dataset containing 1,010 rows and 14 columns of customer orders,
  timestamps, financial metrics, and operational details.

- food_orders_analysis.ipynb
  The complete Jupyter Notebook implementing Tasks 1 through 8:
  * Task 1: Loading data, checking shape, data types, statistical distributions.
  * Task 2: Data-quality assessment (missing counts, duplicates, datetimes).
  * Task 3: Formal cleaning rules table with business rationales.
  * Task 4: Cleaning execution on a copy (work_df) without altering raw_df.
  * Task 5: Feature engineering (Delivery_Time_Minutes, Order_Date, Order_Hour,
            and Platform_Net_Revenue).
  * Task 6: Business analytics answering key management questions.
  * Task 7: Data visualizations (Channel volume, payment methods, weather impact).
  * Task 8: 9-point validation checklist verifying schema and metric integrity.

- config.py
  Centralized configuration file storing:
  * File paths (CSV source, validation report, rejected records).
  * Batch size (100 rows per batch).
  * MySQL host, port, user, password, and database names.
  * Dynamic engine support ('mysql' with automatic 'sqlite' fallback).

- extract.py
  Extracts records from 'food_orders.csv' in batches of 100 rows using Pandas 
  chunking. Does NOT transform or clean data at this stage.

- load_raw.py
  Creates the raw database ('food_orders_raw_db') and table ('raw_food_orders').
  Inserts the raw 100-row batches using database transactions. Preserves original
  values, missing values (NULL), and duplicates exactly as received.

- retrieve_raw.py
  Connects to the raw database and streams records back in batches of 100 rows 
  into Pandas DataFrames, ensuring the raw table remains completely unmodified.

- transform.py
  Implements the core business cleaning and feature transformations:
  * Cross-batch duplicate detection (maintains a seen set of Order IDs).
  * Datetime parsing and chronological validation.
  * Negative delivery duration quarantine.
  * Missing value categorization ('Payment Method' -> 'Unknown'; 
    'Discounts and Offers' -> 'Not Specified').
  * Strict calculation of Platform Net Revenue when all 4 fee components exist.
  * Separates valid records from rejected/quarantined records.

- validate.py
  Performs data quality validation on each transformed batch:
  * Asserts no duplicate order IDs exist.
  * Verifies delivery durations are non-negative.
  * Audits platform revenue math accuracy.
  * Saves rejected records to 'rejected_records.csv'.
  * Generates the formal validation audit file 'validation_report.txt'.

- load_transformed.py
  Creates the analytics database ('food_orders_analytics_db') and table 
  ('cleaned_food_orders'). Loads validated records in 100-row batches using 
  database transactions.

- elt_batch_pipeline.py
  The master workflow runner that coordinates all pipeline steps from extraction 
  to analytics loading, prints the Final Execution Report, and executes SQL queries.

- sql_queries.sql
  Pure SQL queries answering the 6 core business questions directly on 
  'cleaned_food_orders'.

- sql_analysis.py
  Python script to execute 'sql_queries.sql' and print business results.

- validation_report.txt
  Automated text report generated by the pipeline summarizing dataset metrics,
  rejections, data types, and check results.

- rejected_records.csv
  CSV file containing all rejected records (10 duplicate rows) with detailed 
  rejection reasons and batch numbers.

- requirements.txt
  List of required Python libraries (pandas, numpy, mysql-connector-python, 
  matplotlib, seaborn, jupyter, nbformat).

- README.md
  Comprehensive project documentation explaining setup, architecture, and commands.

4. DATA CLEANING STRATEGY & BUSINESS RATIONALE
--------------------------------------------------------------------------------
- Duplicate Rows:
  Removed 10 exact duplicate rows. Retaining duplicates would artificially inflate
  order counts, gross merchandise value (GMV), and restaurant commissions.

- Missing Order Value:
  Intentionally retained as NULL / NaN. Do not impute with 0 or the mean. Imputing
  zero would corrupt average basket size and GMV calculations.

- Missing Fees & Refunds:
  Intentionally retained as NULL / NaN. Missing refunds must not be assumed to be 
  zero, as that would hide operational disputes and customer refunds.

- Missing Categorical Values:
  * 'Payment Method' -> Imputed with 'Unknown'.
  * 'Discounts and Offers' -> Imputed with 'Not Specified' (avoids falsely 
    assuming that no discount was applied).

- Derived Metric: Platform Net Revenue:
  Formula = Commission Fee + Delivery Fee - Payment Processing Fee - Refunds/Chargebacks
  Strict rule: Computed ONLY when all 4 components are available (828 records).
  The remaining 172 records are preserved as NULL to prevent skewed accounting.
